> 이미지 API의 벤더/모델명·구체 엔드포인트·내부 에러코드 문자열·서비스 함수명 → 일반화. (HEIC·EXIF·
> `pillow-heif`·`exif_transpose`는 공개 표준·라이브러리라 그대로 둠.) 매핑은 여기 적지 않는다.

## 무엇을

벌크 사진 보정 기능이 통째로 실패한다는 제보가 프론트에서 왔다. 증상이 묘했다 — 시작하면 진행
카드가 잠깐 떴다가 몇 초 뒤 사라지고, 새로고침하면 영영 안 보이고, **토스트도 에러 UI도 없었다.**
DB를 보니 최근 작업이 전부 `failed`, 아이템마다 외부 이미지 API의 "invalid image file" 류 400이
찍혀 있었다. 원인은 두 겹이었다.

1. **"변환"이 실은 이름 바꾸기였다.** 한 보정 경로가 원본 바이트를 그대로 외부 API에 보내면서
   파일 객체의 `.name`만 `"input.jpg"`로 붙이고 있었다. 바이트는 그대로인데 이름표만 JPEG. 아이폰
   기본 포맷 HEIC가 들어오면 내용은 여전히 HEIC라 엄격한 API가 매직바이트로 거부했다. 같은
   코드베이스의 다른 보정 엔진들은 디코드→재인코드 정규화를 거쳤는데 **이 경로만 그걸 건너뛰었다.**
   게다가 HEIC 디코더(`pillow-heif`)는 의존성에 있었지만 **register 호출이 어디에도 없어** 죽은 코드였다.
2. **실패한 작업이 목록 API에서 제외돼 장애가 안 보였다.** 검토-대기 목록 쿼리가
   `status in (running, completed)`로 필터링하고 있었다. 작업이 `failed`로 떨어지는 순간 목록에서
   빠졌고 → 카드가 사라졌고 → 사용자는 무슨 일이 있었는지 볼 표면 자체가 없었다. 상세 API는 실패
   작업을 정상 반환했는데, 정작 목록이 그걸 가렸다.

fix는 세 갈래. (a) 외부 호출 직전 **pre-flight 정규화** — HEIC 디코더 등록 + 디코드 + **EXIF 방향
보정**(`exif_transpose`, 빼면 아이폰 세로 사진이 메타데이터 사라지며 눕는다) + RGB 변환 + 다운스케일
+ 용량 상한 아래로 JPEG 재인코딩. (b) 아이템 에러를 raw 제공자 덤프 대신 **클라이언트가 분기
가능한 구조화 코드**(형식 미지원/용량 초과/손상/일반)로. (c) 목록 쿼리가 최근 24시간 실패 작업을
포함하도록 넓혀 실패 카드를 띄움. (리뷰가 (a)의 EXIF 방향 누락을 1라운드에서 지적 → 다른 두 경로가
이미 `exif_transpose`를 쓰는 걸 확인하고 수정, 2라운드 통과.)

## 왜 (교훈)
- **"변환했다고 믿었지만 이름만 바꿨다"** — 파일 객체에 확장자/이름을 붙이는 건 디코더 힌트일 뿐
  내용 변환이 아니다. 매직바이트로 검사하는 엄격한 API엔 이름표 위장이 안 통한다.
- 같은 기능의 여러 백엔드/엔진을 둘 때 **공통 전처리(디코드·EXIF 방향·정규화)를 공유하지 않으면**
  한 경로만 조용히 깨진다. "비슷하니까"로 새 경로를 추가할 때 갈라진다.
- **장애를 안 보이게 만드는 건 종종 두 번째 결함이다.** 전 아이템 실패(1번)만도 나빴지만, 진짜
  악질은 실패 작업을 목록에서 빼버린 2번 — 그 탓에 "조용히 사라지는 카드"로만 보였다. 실패를 만드는
  코드와 실패를 숨기는 코드는 보통 다른 파일에 있다. 에러 컨트랙트(구조화 코드 + 실패를 일정 기간
  목록에 남기는 윈도우)를 처음부터 설계해야 "조용한 장애"가 "보이는 실패"가 된다.
- **라이브러리가 의존성에 있다 ≠ 동작한다.** `pillow-heif`는 설치돼 있었지만 register 한 줄이 없어
  죽은 코드였다. 실제 코드 경로에서 호출되는지 확인해야 한다.

## 외부에 공유해도 좋은 부분
- 파일 객체 `.name=".jpg"`는 변환이 아니라 이름표 — 매직바이트 검사 API엔 안 통한다는 함정.
- 같은 기능의 여러 엔진에 공통 전처리를 공유 안 하면 한 경로만 조용히 깨진다는 설계 교훈.
- 실패 작업을 목록 API에서 제외하면 장애가 사용자에게 안 보인다 → 실패를 일정 기간 목록에 남기고,
  raw 제공자 에러 대신 클라이언트 분기 가능한 구조화 에러 코드를.
- 재인코딩 시 EXIF 방향(`exif_transpose`)을 먼저 적용 안 하면 사진이 눕는다.
- 라이브러리가 requirements에 있어도 register/초기화 호출이 없으면 안 동작한다.

## 외부에 공유하면 안 되는 부분 (redaction 시 참고)
- 외부 이미지 편집 API의 벤더/모델명과 구체 엔드포인트 → "외부 이미지 편집 API"로 일반화.
- 내부 에러코드 문자열·엔드포인트 경로·서비스 함수명 → 패턴만, 식별자 일반화.
- 본 건은 운영자 본인 계정 발생(외부 고객 영향 아님), 계정 식별 정보 본문 없음. (열거 안 함 — public.)
