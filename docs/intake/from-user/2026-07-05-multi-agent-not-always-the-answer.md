> 이 글은 **운영자↔AI 문답**으로 쓰였다(역방향 인터뷰: 운영자가 AI에게
> 묻고 AI가 답함). **fact 분리:** 현재-사실 주장(Cognition의 single-threaded
> linear agent/Flappy Bird, Anthropic의 90.2%·토큰 15x)은 web 검증 → 인용 가능.
> Anthropic의 폭주 실패모드(50개 서브·끝없는 검색)는 *정성* 서술이라 그대로 두되
> '또 10x' 같은 추가 수치는 원문에 없어 삭제. '업계 수렴'은 두 사례로부터의
> 정리(추론)로 낮춤. **추론 라벨:** '한 질문으로 갈린다'는 프레이밍,
> 3세금·임계점 부등호, 회의 비유는 운영자/AI의 정리로 명시(단정 아님).
> **redaction:** 회사·소속·클러스터·시크릿 없음. redteam은 공개 오픈소스라
> 언급 가능. 독자 질문자는 '한 독자'로 일반화. 산업 MAS는 일반지식 수준
> (특정 벤더 사례 깊이 다루지 않음).

## 핵심 (문답에서 도출)

1. **무조건 정답은 아니다 — 한 질문으로 갈린다.** "병렬로 쪼갠 조각들이 서로의
   암묵적 결정을 몰라도 되는가?" 몰라도 되면(읽기·탐색) 멀티가 이기고, 알아야
   하면(쓰기·일관 산출) 오히려 독이 된다.
2. **적합:** 읽기 중심·탐색형(breadth-first), 조각이 충돌 안 하는 분해, 고부가
   가치라 토큰 15배를 흡수 가능. (Anthropic 리서치 시스템: orchestrator-worker,
   3~5 서브 병렬, 단일 Opus4 대비 90.2% 우위, 토큰 ~15x.)
   **부적합:** 쓰기 중심·하나의 일관 산출물(코드 작성 = Flappy Bird 프랑켄슈타인),
   순차 의존, 저부가가치. (Cognition: single-writer + 필요시 압축 전용 LLM.)
3. **실전형은 대칭형이 아니다**(두 사례로부터의 정리) — '지휘자 1이 전체 컨텍스트를
   쥐고, 일회성 고립 서브를 정찰병처럼 띄워 압축 요약만 받음.' 싱글의 확장.
4. **크로스-모델 검증이 모순 아닌 이유.** 분업(쓰기)은 컨텍스트 공유가 *필요*,
   독립검증(판단)은 컨텍스트가 *없어야* 함 — 정반대 축. 저자와 같은 모델은
   고무도장, 다른 계열은 동의할 이유가 없음. redteam = 단일 작성자 + 독립 검증자
   (Cognition의 '단일 스레드 선형 에이전트' 원칙을 지킨 것; 'single writer'는 이
   글의 요약 표현). 규칙: **쓸 땐 모으고, 판단할 땐 떼어낸다.**
5. **늘리면 왜 나빠지나 — 세 가지 세금.** ① 조율(순진하면 n² 경로) ② 컨텍스트
   파편화(전체를 끝까지 보는 존재가 없음, 압축=손실) ③ 오류 복리(틀린 전제 증폭
   + 폭주 시 15배 위에 낭비가 더 쌓임). 임계점: 추가 이득 < 세금이 되는 순간부터
   나빠짐. 읽기는 임계가 높고 쓰기는 낮음.
6. **회의 비유(추론용).** 2명 회의보다 8명 회의가 항상 더 나은 결정을 못 내리는
   이유 — 추가 두뇌의 이득을 소통 오버헤드가 먹음. (Brooks's Law와 같은 결이나
   엄밀 인용 아님, 직관용.)
7. **'멀티에이전트'라는 단어의 함정.** LLM 멀티에이전트 ≠ 산업 제어의 Multi-Agent
   System(로봇 군집·분산 제어 등 오래된 분야). 같은 단어인데 성숙도가 정반대라,
   질문의 의미부터 확인해야 함. 이 글의 범위는 소프트웨어(LLM)로 못박음.

## 연결

- 검증이 loop engineering의 핵심([loop-engineering-verifier]), 위임은 붙잡는
  지점을 옮기는 것([i-didnt-design-it-i-delegated])과 같은 결.

## 외부 공유 불가

- 독자 질문자 신원(일반화 '한 독자'). 회사·소속·클러스터·시크릿 없음. 산업 MAS의
  특정 벤더 사례는 주제 밖이라 일반지식 수준으로만. redteam은 공개 오픈소스.
