## 무엇을

사진검색 서비스의 검색 스택을 손보면서 두 가지를 결정했다. (1) 임베딩을 **bge-m3 + bge-reranker
조합에서 Qwen3-VL-Embedding으로 교체**, (2) **리랭커를 아예 제거.** 교체 이유와 제거 이유는 다르다.

- **임베딩 교체 이유**: 사진검색은 단순 단어 일치가 아니라 *의미적·멀티모달 맥락*을 잡아야 한다.
  Qwen3-VL-Embedding은 텍스트·이미지·비디오를 함께 다루는 멀티모달 임베딩이라 사진검색에 맞다.
- **리랭커 제거 이유**: 아래.

## 리랭커를 뺀 이유 (테스트 중 발견)

킬러 시나리오 하나가 가정을 무너뜨렸다. **"아기가 나온 사진 다 찾아줘"** 같은 쿼리는 수천 장을
돌려줘야 한다 — 이건 *precision*(상위 몇 개가 정확한가)이 아니라 *recall*(있는 거 다 끌어오는가)
문제다. 그런데 리랭커는 벌크에 구조적으로 안 맞았다:

- **(a) 비용/지연 폭발.** cross-encoder 리랭커로 수천 개 후보를 일일이 점수 매기는 건 너무 느리고 비싸다.
- **(c) 컷오프 절단.** 리랭커 파이프라인은 본질적으로 상위 k를 reorder하는 구조라, "다"가 잘려나간다.

요지: **리랭커는 precision@(작은 k) 도구지, "다 찾아줘"라는 recall/벌크 도구가 아니다.**

## 왜 쿼리 타입으로 분기하지 않았나 (진짜 결정 근거)

가장 자연스러운 반론은 "벌크 쿼리엔 리랭커 끄고, 콕 집는 쿼리('내 아들 촛불 부는 그 사진')엔 켜라"
는 분기다. 고려했고, **포기**했다. 두 가지 이유:

1. **자연어가 조건을 깔끔히 안 가른다.** 한 문장에 *넣을 조건*과 *뺄 조건*이 섞여 있으면(예:
   "A는 빼고 B는 다 보여줘"), LLM이 이걸 완벽하게 분해해 "이건 벌크/이건 정밀"로 라우팅하는 건
   불가능에 가깝다.
2. **설령 갈라도 의도를 추론 못 한다.** "다 보여줘"가 누군가에겐 *문자 그대로 수천 장 전부*고,
   누군가에겐 *그냥 많이*다. 같은 표현의 의도를 시스템이 함부로 단정하면 안 된다.

→ **자연어 기반 하이브리드 라우팅은 신뢰 불가**라고 결론. 그래서 분기 대신 리랭커를 통째로 뺐다.
(임베딩만으로도 정밀도가 멀쩡했던 게 이 결정을 뒷받침했다 — 처음부터 검색 품질이 나쁘지 않았다.)

## 대체 — MRL 2단계 (리랭커 없이 정밀도 회복)

리랭커를 빼고 정밀도를 보완할 방법을 고민했는데, 생각보다 쉬웠다. **Qwen3-VL-Embedding에는
MRL(Matryoshka Representation Learning)이 적용돼 있다** — 하나의 임베딩을 여러 출력 차원으로
truncate해도 의미가 유지된다. 공식 스펙상 기본 1024차원이고 `truncate_dim`으로 64·128·256·512·
1024·1536·2048 출력이 가능하다(출처: HF·arXiv).

이걸로 2단계를 만들었다:
- **저차원 1차 필터** — 낮은 차원으로 전체를 빠르고 싸게 훑어 후보를 좁힌다.
- **고차원 2차 정밀화** — 좁혀진 후보만 높은 차원으로 다시 비교해 순위를 정밀화한다.

별도 cross-encoder 리랭커 모델 없이, **같은 임베딩 한 모델 안에서** 리랭커와 *비슷한* 효과를 낸다
(로직은 다르다 — 이건 차원을 달리한 2단계 dense 검색이지 cross-encoder 재점수가 아니다). 결과:
정밀도 멀쩡, 벌크 가능, 스택 단순화(모델 하나 줄었다).

## 외부에 공유해도 좋은 부분
- **리랭커는 precision@k 도구지 recall/벌크 도구가 아니다** — "다 찾아줘"형 쿼리가 리랭커 가정을 깬다.
- 벌크 vs 정밀을 **자연어로 라우팅하는 것이 왜 신뢰 불가능한가**(조건 혼재 + 의도 추론 불가).
- **MRL coarse-to-fine**(저차원 1차→고차원 2차)로 별도 리랭커 없이 한 모델 안에서 정밀도를 회복하는 패턴.
- 사진검색엔 멀티모달 임베딩(Qwen3-VL-Embedding)이 단어일치 임베딩보다 맞다는 선택.

## 외부에 공유하면 안 되는 부분 (redaction 시 참고)
- 내부 컬렉션명·인프라 식별자·정확한 내부 차원 튜닝값 → 제외("저차원→고차원" 패턴 + 모델 지원
  차원집합 수준만). 모델명(bge-m3, Qwen3-VL-Embedding/Reranker)은 공개 모델이라 유지.
- "수천 장"은 illustrative 규모. 실제 인덱스 크기·QPS·비용 수치는 비즈니스 민감 → 제외.
