## 주장 (운영자 1인칭)

**클릭(메뉴/버튼)으로 되는 모든 액션은 대화로 에이전트에게 시켜서도 가능해야 한다 —
"대화-패리티".** 대화창은 이미 완벽한 UX인데, 나머지 작업이 거기서 seamless하지 않다.
"메뉴를 없애라"가 아니다(옛 UX에 익숙한 유저는 오히려 대화식이 불편할 수 있음을 인정).
메뉴는 둬도 된다 — 단, 클릭으로 되는 *모든* 것에 **대화 경로가 함께 존재**해야 한다.
출력은 버튼·링크로 렌더돼도 좋다. 진입점이 대화로도 열려 있어야 한다는 것.

## 라이브 장면 (2026-06, UX만)

운영자가 웹 Claude 세션에서 "이전 대화 목록 조회 가능해?"라고 물었다. 답변 요지: 과거 대화
*원문 검색*은 이 세션에서 기본 비활성이고, 쓰려면 **Settings → Profile에서 "Search and
reference past chats" 토글을 켜야** 한다. — 즉 **대화형 회상 기능을 켜는 것부터 메뉴
다이빙**이다. "대화로 켜줘"가 안 된다. 대화형 기능의 진입 자체가 비대화형.

(운영자가 붙인 실제 응답에는 사내 인프라가 다수 노출됐으나 본 정제본·발행 글에서 전량 제외.)

## fact-check (발행 시 귀속)

2026년 현재 세 제품 모두 **과거 대화를 대화로 불러오는 기능 자체는 있다** — 그래서 "아직도
클릭만 된다"는 *현재 사실로는 틀림*. 단정/추측 분리 정책상 이대로 못 씀:
- Claude: chat search + memory(2026-03-02 전 유저 무료), "찾아줘"로 RAG 호출.
- ChatGPT: past chat 검색 + Memory Sources(2026-05).
- Gemini: 과거 대화 recall(정밀도는 상대적으로 낮음).
- 단 sidebar search는 제목만 매칭(내용 검색 안 됨, Claude) → 회상은 *보조*로 숨고 리스트가 주력.

→ **프레임**: "아직도 클릭시킨다"(약함·부정확)가 아니라 **"recall은 대화형으로 만들어
패리티가 작동함을 *증명*했는데, 켜기·도움말·설정·공유·export 등 나머지는 여전히 클릭 전용 —
패리티가 절반에서 멈췄다"**(2026 현재 정확, 주장은 더 셈). 라이브 장면이 그 절반의 증거.

디자이너 외부 근거(귀속): "chat이 늘 정답은 아니다, 하이브리드(chat+버튼)가 best"라는 공개
논의 다수 → 운영자의 *패리티*(대체 아닌 공존) 주장과 수렴. 운영자 주장 = "하이브리드를 제대로
하면 = 클릭 가능한 *전부*에 대화 경로".

## 왜 안 바뀌나 (운영자 추측 — *추측으로* 표기)

운영자는 "이건 내 추측이고, 실제 디자이너 의견이 궁금하다"고 단서. 복합 원인 추정:
① 초기 에이전트 능력 부족(처음엔 이 이유가 가장 강했을 것) → ② 그 능력에 맞춘 최적화 UX →
③ 관성(OpenAI 성공→모두 모방) → ④ "LLM 서비스는 다 이렇게 생겼다"는 유저 경험 누적 →
⑤ 유저가 그 디자인에 적응. **원래 제약(능력)은 풀렸는데 형태만 남았다**는 경로의존 서사.

## Ascendy 자사 실천 (원칙만 — 구현·로드맵 제외)

- **이미 한다**: 개인적으로만 동작하는, 클릭으로 가능한 기능 대부분을 자연어로도 가능하게 해둠.
- **원칙적 예외(분별)**: 사진을 외부 공개하는 것처럼 **비가역·프라이버시 영향이 큰 액션은
  일부러 에이전트가 못 하게**, 사람의 명시적 클릭으로 남김. 패리티는 독단이 아니라 분별 —
  되돌릴 수 없는 외부 노출엔 사람 게이트. (구현 *방법*은 비공개.)
- **피드백도 대화로(일반 원칙)**: 옛 UX는 "피드백 폼 찾아→열고→보내고→기다림". 대화-패리티
  버전은 불만을 그냥 대화창에서 말하면 잡혀 라우팅돼야 한다 — 사용자가 capture·route의 병목이
  되지 않게. (이건 *지향하는 설계 원칙*으로만 서술. 특정 자동화 파이프라인을 "구축 중"이라
  주장하지 않음 — 미공개 로드맵 제외.)

## 외부에 공유해도 좋은 부분
- 대화-패리티 주장(클릭 가능한 전부에 대화 경로), "대체 아닌 공존"이라는 정교화.
- "절반의 패리티" 프레임 + 2026 현재 recall 기능 현황(귀속 가능한 공개 사실).
- 디자이너 하이브리드론과의 수렴, 경로의존 서사(추측은 추측으로).
- Ascendy의 분별 있는 예외(비가역·공개 액션은 사람 게이트)라는 *원칙*.
- 피드백은 폼이 아니라 대화로 와야 한다는 *일반 설계 원칙*(capture→route, monitoring 글과 연결).

## 외부에 공유하면 안 되는 부분 (redaction 시 참고)
- 운영자가 붙인 웹 Claude 응답 속 **사내 식별자 전부** → 전량 제외(무엇이었는지는 여기 열거
  안 함 — 이 파일도 public).
- Ascendy 피드백 자동화의 **구체 구상**은 미공개 → "우리가 구축 중"으로 쓰지 말 것. 일반
  설계 원칙으로만.
- 프라이버시 게이트의 **구현 메커니즘**(어떻게 막는지)은 load-bearing → 원칙만, 방법 제외.
