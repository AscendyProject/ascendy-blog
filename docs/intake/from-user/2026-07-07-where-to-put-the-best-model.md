> 인터뷰(/interview)로 도출. **1인칭 베팅:** '실행에 최고 모델은 과잉'은 운영자
> 견해임을 명시(설교 아님). **모델명:** Opus 4.8·Fable 5·Sonnet·Haiku(Anthropic,
> 컨텍스트 확정), GPT-5.5(OpenAI 2026-04)·Gemini 3.5 Flash(Google 2026-05,
> 에이전트·코딩용으로 더 빠르고 저렴함을 내세우는 포지셔닝 — 직접 인용 아닌
> 패러프레이즈)·Codex는 web 검증된 실존 2026 모델. **벤치마크 아님을 명시** — 운영자의 실제 세팅(2026년 중반 기준).
> **redaction:** '회사·같은 파트·동료'는 일반화(회사명·파트명·동료 식별 없음),
> 예산 주머니(개인 vs 회사)도 일반 서술. 동료 패턴 1·3은 관찰된 다양성으로만 쓰고
> 그들의 이유는 지어내지 않음(운영자 여정만 인과로). 시크릿 없음.

## 핵심 (인터뷰에서 도출)

1. **관찰.** 같은 파트 사람들, "모델 섞으면 낫다"엔 만장일치인데 실제 배치는 제각각:
   - (1) plan+implement 경량, review만 좋은 모델
   - (2) plan 좋은 모델 → implement 경량 → review 또 다른 좋은 모델 (운영자)
   - (3) 전부 최고, review만 다른 모델
2. **세 배치 = "품질을 어디에 넣을까" 베팅.** 근데 그 베팅을 정하는 건 취향이 아니라 제약.
3. **운영자 여정: 3 → 벽 → 2.** 전부 최고로 시작 → 너무 오래 걸리고 토큰 커서 몇 작업 만에
   리미트 → 예산 조건 걸고 조합 요청 → 2번 적용 후 만족해 정착. (AI 넷 만장일치는
   '믿어서'가 아니라 예산 조건 걸면 나오는 '당연한 산수'였고 사후 확인에 가까움.)
4. **안 돌아가는 이유(핵심).** 최고 모델(Opus 4.8·Fable 5)이 짜도 리뷰(Codex 등)에서
   고칠 게 나온다 → 완벽 원샷이 불가능하면 *빨리 결과 내고 빨리 피드백 받아 루프를 빨리
   도는 것*이 최고. 실행엔 'plan 구현 가능한 최소선'만(Haiku는 그것도 못 함, Sonnet/Gemini
   Flash는 됨), 그 위는 리뷰가 걷어내니 과잉. → 제약은 타협을 강요한 게 아니라 '실행에 최고
   모델은 낭비'를 가르쳐줌.
5. **실행 모델 선택도 예산.** 집=Sonnet, 회사=Gemini 3.5 Flash — 품질 아닌 예산 주머니.
6. **결론.** 남의 배치를 베끼지 마라. 네 제약(예산·레이트리밋·병렬 개수·작업 모양)이
   네 배치를 정한다.
7. **코다.** 주간 한도 소진으로 마비된 이틀 — 답답하지만 멈춰 생각하게 됨. 정신없이 구현할
   땐 못 본 걸 발견(강제된 리뷰).

## 연결

- 검증이 loop engineering의 핵심([loop-engineering-verifier]), 멀티에이전트는 무조건
  정답 아님([multi-agent-not-always]: 쓸 땐 모으고 판단할 땐 떼어낸다), 토큰은 생산성이
  아님([token-usage-not-productivity])과 같은 결.

## 외부 공유 불가

- 회사·같은 파트·동료 식별(일반화). 예산 주머니 세부(일반 서술). 동료의 배치 이유(추정
  금지). 시크릿 없음. 모델명은 공개 실존 모델이라 게재 가능하나 벤치마크 아닌 '내 세팅'으로 명시.
