> redteam 팀 인테이크 정제본. **canon honesty(원문이 명시한 정직성 계약):**
> "완전 자율(fully autonomous)"로 과장 금지 — 사람이 각 런의 시작(goal.md)과
> 끝(PR 머지)에 손을 대고, 오퍼레이터 에이전트가 엔진 갭을 상당히 수습했다.
> 정확한 프레이밍은 "자율 + 오퍼레이터 수습, 그 수습이 다음 개선의 재료".
> 진행 중 작업을 "shipped"로 쓰지 말 것. 발견됐지만 아직 안 고쳐진 갭이 하나
> 남아 있으므로(planner 관련) "전부 고쳤다"로 쓰지 말 것. **redaction:** 소스가
> 전부 공개 repo(Apache-2.0)라 코드/PR 노출 이슈 없음. 사업/고객 정보 없음.
> GitHub 계정명은 강조 불필요. 특정 이슈 번호는 본문에서 최소화(가독성).

## 핵심 (인테이크에서 도출)

1. **크럭스: 자율성 ↔ fail-closed는 상충하지 않는다.** 자율을 늘리는 방법이
   게이트를 없애는 게 아니라, *판단 없는 일만 위임하고 계층을 오히려 하나 더 얹는*
   것이다.
2. **자율 드라이버.** 골 하나(goal.md) 주면 decompose→start 후, status를 읽고
   진단→허용된 조치→resume 루프를 모든 드래프트 PR이 열릴 때까지 돎. **머지는 절대
   안 함**(드래프트 PR 스택 = 유일한 인간 체크포인트). 허용 조치=판단 없는 기계적
   단계만; hard stop=분해 거부·같은 이유 2회 deferral·보안 경계·과다 반복.
3. **릴리스 자동화(v0.7.0, 하네스가 스스로 컷한 첫 릴리스).** 사람의 결정(머지 +
   승인 클릭 한 번)만 남기고 그 사이 기계적 단계 전부 제거. 버전 드리프트 가드 +
   actor 게이트로 fail-closed. "자동화가 판단을 대체하는 게 아니라, 결정 사이의
   기계 단계를 없앤다."
4. **에피소드 ①: 자율성 부여 문서조차 적대 리뷰에 깎였다.** 권한 플레이북 초안이
   "스테일 브랜치는 삭제"였는데, 크로스-모델 리뷰어가 "엔진은 defer하지 삭제 안 함;
   무조건 삭제 허용은 미머지 데이터 손실 경로"라고 major 지적 → ancestor 확인 후에만
   삭제, 아니면 rename-aside. *에이전트에게 자율성을 주는 문서마저 적대 리뷰를 통과해야
   한다.*
5. **에피소드 ②: scope가 리뷰 품질을 결정한다.** 태스크별 크로스-모델 리뷰가
   APPROVED로 통과시킨 무결성 결함을, 통과 후 돌린 *스택 통합* 적대 리뷰가 잡았다.
   태스크별 리뷰는 자기 델타만 보므로 예외 로직×커밋 귀속의 상호작용이 안 보였고,
   스택 전체를 봐야 드러났다. 고칠 때도 인라인 패치 대신 결함을 워커에 리뷰 피드백으로
   되돌려 고치고 다른 모델이 재검증(심판은 끝까지 다른 모델).
6. **에피소드 ③: fail-closed는 워커의 거부에도 있다.** 구현 워커가 상호 모순된
   스펙(기존 테스트 무수정 통과 vs 그 테스트가 고정한 규칙 변경)을 3번 거부하고
   모순을 보고했다 — 억지 통과(테스트 몰래 수정) 대신.
7. **정직한 한계.** 두 자율 런 모두 사람이 시작·머지했고 오퍼레이터가 엔진 갭을
   수습했다. 그 수습들이 곧 다음 개선 이슈가 됐다. "자율 + 수습의 순환"이 정확한 그림.
