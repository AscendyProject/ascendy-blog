> redteam 팀 인테이크 정제본. **교훈 수준 서술(블로그팀 A안 결정):** 리뷰가 잡은 보안
> 결함들은 *익스플로잇 리스트/바이트값/단계별 재현*으로 쓰지 않고, "라운드마다 더 미묘한
> 우회가 나왔다"는 에스컬레이션 서사 + 2~3개 개념 예시로만 일반화. **미해결 하드닝:** 기본
> 경로용 별도 하드닝이 별개 이슈로 분리돼 아직 열려 있으나, 오케스트레이터가 clean 트리에서
> 도는 배치 드라이버라 현실 위험이 낮다는 맥락을 함께 적어 '미패치 보안 구멍'으로 오독되지
> 않게 함(공개 repo에 이미 기록됨). **redaction:** 다운스트림 채택자/고객/파트너 언급 금지,
> 공개 repo의 PR/이슈만 근거. 특정 이슈/PR 번호는 본문에서 최소화(가독성). 대상은 Ascendy
> 제품이 아니라 오픈소스 하네스 자신 → 크레덴셜 무관, 수정 머지·공개됨.

## 핵심 (인테이크에서 도출)

1. **겉보기 단순 작업.** 기본 모드에 이미 있는 커밋 패턴을 비-기본 모드에 복제하는 일처럼 보였다.
   그런데 교차-프로바이더 적대 리뷰(한 모델이 구현, 다른 프로바이더 모델이 diff를 적대적으로 리뷰)가
   **plan 5 + code 7 = 12라운드**에 걸쳐 점점 깊은 결함을 캐냈다.
2. **갈림의 crux.** 옵션(설계)엔 양쪽 동의. 갈린 건 "무엇을 이번에 고치고 무엇을 분리하느냐의 경계선"과
   "구현자가 주장한 안전 속성을 어느 강도로 증명하느냐". 구현자는 "선재 문제는 분리하자"를 반복했고,
   리뷰어는 매 라운드 **그 경계를 우회하는 더 구체적인 경로**를 들고 왔다. 추상적 합의가 아니라 공격
   표면의 구체성에서 갈렸다.
3. **에스컬레이션(교훈 수준).** 신뢰 입력(상태 파일에서 읽는 경로) 하나가 여러 방식으로 검증을 우회 →
   개념 예시: 숨은 제어문자가 검증을 통과한 뒤 경로를 쪼갬 / 인덱스 전체 커밋이 무관한 스테이징 파일을
   빨아들임 → 명명된 경로만 커밋 / 느슨한 텍스트 매칭이 의도보다 많이 잡음 → 정확 일치. 각 라운드마다
   빈 저장소에서 실제 동작을 검증하고 회귀 테스트 추가.
4. **교훈.** ① "기본 경로에 이미 있으니 괜찮다"는 위험한 면죄부 — 주장한 안전 속성은 코드로 증명되어야
   하고, 경계는 면죄부가 아니라 명시적 분리 이슈로 문서화하되 그 경계를 우회하는 경로는 그 자리에서 막는다.
   ② 신뢰 입력은 전수 검증. ③ 교차 '프로바이더' 적대성이 load-bearing. ④ 단순함의 함정 — 비-기본 모드라
   검증이 느슨했던 곳이 가장 많은 라운드를 유발.

## 연결

- 검증이 loop engineering의 핵심([loop-engineering-verifier]), 리뷰 도구가 저자를 잡았다
  ([review-tool-caught-the-author]), 자율성과 fail-closed([autonomy-and-fail-closed])와 같은 결.
  이 글의 무게중심은 *"단순해 보일수록 검증이 느슨하고, 교차-프로바이더 적대성이 그걸 반증한다"*.

## 외부 공유 불가

- 다운스트림 채택자/고객/파트너(언급 금지). 보안 결함의 익스플로잇 디테일(바이트값·단계별 재현 미기재,
  교훈 수준만). 미해결 하드닝은 '현실 위험 낮음(clean 트리 전제)' 맥락과 함께. 특정 이슈/PR 번호 최소화.
  대상은 오픈소스 하네스 자신 → Ascendy 제품 내부·크레덴셜 무관. 시크릿·클러스터 없음.
